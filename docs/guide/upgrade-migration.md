# 升级与迁移

::: info v0.5.0 已发布 · 旧版需显式迁移
[v0.5.0 正式 Release](https://github.com/LinyuFiee/QQON-Panel/releases/tag/v0.5.0) 已提供 format3 管理器与 Windows 升级入口。已有 v0.4.0 安装先确认迁移管理器，再单独升级程序；不会自动接管旧安装或重置账号。发布/CI 结果不等于真实系统升级恢复验收，详见 [支持矩阵](./support-matrix)。
:::

## 三种操作不要混淆

| 操作 | 作用 | 不能承诺的事 |
| --- | --- | --- |
| 普通程序升级 | 在兼容的管理器与数据格式下切换到已发布的新程序 | 不会自动替换安装器、降级或做任意数据迁移 |
| 管理器迁移 | 显式更新已知旧安装器/配置，使其理解新发行协议 | 不会自动接管手动安装或被修改的脚本 |
| 数据迁移 | 数据结构变更时的独立计划 | 不属于当前 schema 1 普通升级/回退承诺 |

面板网页只提供检查与说明，不获得管理员/root 权限，不代替用户在目标机显式运行升级器。重启会使内存会话失效，账户、TOTP 和私有配置应保留。

## v0.4.0 现有安装

v0.4.0 管理器验证 format2 与六个固定附件；只能消费它理解的发布格式，不能直接升级到 v0.5.0 的 format3。保留旧版无需重复安装，升级则按下节显式迁移管理器。

只有明确兼容的 format2 正式 Release 才能由旧管理器按其帮助使用 `sudo panel-update` 或指定版本；不要编造不存在的 v0.4.x 附件。旧管理器拒绝 format3 是预期行为，不能删校验或伪造六附件清单来升级。

## v0.4.0 → format3 管理器迁移 {#manager-migration}

使用已发布的 [v0.5.0 正式安装入口](./installation) 启动显式迁移。不能以 `main` 的可变脚本替代正式发布来源；`--yes` 不会隐式批准更换管理器，仍需单独终端确认。

仅允许识别已知官方 v0.4.0 管理器：

| 文件 | 官方 SHA-256 |
| --- | --- |
| v0.4.0 `install.sh` | `bc78f2ec682704bb5beb965806ec56e511827f6d3451949a03d5b40db535eb91` |
| 对应 `update.sh` 包装入口 | `5cdc4f05cce7189b7212e5b12496e0754985c45c1462fc2ce0aa1a86f81b1408` |

文件哈希只是识别条件之一，还需核对旧安装记录、程序身份与 unit，不能仅信任可变配置里写的摘要。

迁移顺序：

1. 管理员先备份私有数据，确认旧安装属于可识别的官方版本。
2. 若旧升级事务未结束，先使用已知旧管理器恢复；不要用新管理器跳过旧事务。
3. 新安装器解释协议差异并取得显式确认，再单独备份、记录管理器迁移事务。
4. 原子更新受保护的管理器/配置，保留原安装身份、监听与 unit 的有效配置；失败恢复旧管理器、配置和 unit。
5. 迁移完成后再按新协议进行程序升级。普通程序事务与管理器迁移不是一个隐式动作。

手工复制的二进制、format1 开发安装、未知或修改过的脚本不在自动迁移范围。拒绝迁移时应停下来制定独立迁移计划，不使用“强制接管”或伪造安装记录。

## 普通升级的验证顺序

v0.5.0 的 Linux 和 Windows 升级器都先持锁，再核对固定仓库的 Release 元数据、尺寸、SHA-256、唯一归档成员、目标平台、程序内嵌版本和数据 schema。下载与校验完成前不停止旧服务。

通过校验后，在程序文件系统暂存和保留旧程序，落盘事务，再停止服务、切换、启动，核对本机健康接口返回的版本与 schema。Windows 还必须等待进程退出和文件解锁。不能仅凭下载完成、解压成功或服务命令返回成功判断升级成功。

## 回退与恢复

- 普通升级拒绝降级或不同数据 schema。当前数据 schema 为 `1`。
- 回退针对程序，不重置管理员、TOTP、数据目录或账号锁文件。
- 新版启动/健康校验失败时尝试恢复旧程序；恢复失败必须保留错误与事务，不报告成功。
- Linux 旧格式事务使用 `prepared` / `ready` 状态；未结束时下次运行先校验并恢复，成功后结束本次调用，不自动重试失败版本。
- 断电、磁盘故障或权限破坏可能阻止恢复；临时目录测试不是灾难恢复保证。

保留 `/etc/server-panel/update-transaction.json`（Linux）或 Windows 对应受保护事务及旧程序备份。不要删除事务、锁或私有目录来“清空状态”。遇到失败按 [故障排查](./troubleshooting) 收集必要的非敏感信息。
