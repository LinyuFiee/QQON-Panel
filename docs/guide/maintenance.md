## 中文维护入口

v0.6 拟提供 `qqon` 中文菜单，也可按下表选择维护命令。入口位置、最终参数与输出以正式 Release 为准，不把开发脚本混入现有安装。

| 命令 | 用途与边界 |
| --- | --- |
| `qqon` | 打开中文维护菜单，按提示选择操作 |
| `qqon status` | 只读查看本机服务与安装状态 |
| `qqon url` | 只读显示已配置的访问地址；不证明外网可达 |
| `qqon start` | 启动已安装的面板服务 |
| `qqon stop` | 停止面板服务 |
| `qqon restart` | 重启面板服务，会中断访问 |
| `qqon logs` | 查看运行日志；分享前脱敏 |
| `qqon update` | 校验并更新到兼容的正式程序版本；不自动改为公网访问 |
| `qqon backup` | 先停服并确认进程退出，再生成含敏感 data 的一致备份 |
| `qqon config` | 显式修改访问配置，按事务校验、切换与恢复 |
| `qqon tls renew` | 更新自签证书，按事务保留旧状态并校验切换 |

`status`、`url` 不安装依赖、不启停服务、不修改配置，也不恢复未完成事务。显示服务正常或生成了公网 IP 链接，不等于云安全组、NAT 或防火墙已允许外部访问。

## 权限与服务身份

安装和维护写操作由 **Linux root** 或 **Windows 管理员终端**执行；这不意味着面板服务以管理员身份常驻。

- Linux 保留固定 `server-panel` 账号与 `server-panel.service`。
- Windows 保留 `QQONPanel` 服务与 `NT SERVICE\QQONPanel` 虚拟账号。
- 不因升级或修改访问配置而重建账号、接管不明安装，或放宽私有数据权限。

## 备份与事务

备份前先停止服务并确认进程退出，再复制私有数据，避免运行中写入产生不一致副本。备份包含账号及其他敏感 `data`，须保存在受保护位置；不要提交仓库、上传公开网盘或贴入工单。备份完成后按操作结果确认服务状态，不把“文件已复制”当作服务已恢复。

`config` 与 `tls renew` 按事务执行：先校验并保留旧配置/证书，再切换与检查；失败按事务记录恢复。不要删除锁、事务或旧文件来强行重试。磁盘损坏、权限变化和物理断电仍可能阻止恢复，不承诺绝对回退。

## 从 v0.4 / v0.5 迁移

待 v0.6 正式发布后，按以下顺序处理已有受管理安装：

1. 备份私有数据，识别官方旧管理器，经管理员**显式确认**迁移新管理器；保留旧访问方式、端口、服务身份和数据。
2. 单独升级到支持新配置的程序，先确认新程序在原访问方式下正常运行。
3. 如需公网 IP HTTPS，再通过 `qqon config` 确认公网 IPv4 和访问配置；不能先把新公网配置交给旧程序。

迁移或普通升级不会因新安装默认值变化而自动开放公网。未知手动安装、被修改的管理器不能强制接管；现有迁移边界见 [升级与迁移](./upgrade-migration)。
