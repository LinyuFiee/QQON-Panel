# 故障排查

## 提示需要新版或不兼容 Release {#pending-release}

**当前已发布预览版为 [v0.6.0](https://github.com/LinyuFiee/QQON-Panel/releases/tag/v0.6.0)**。仍提示版本不兼容、缺少 Windows 附件或需要新版时，先停止并查看 [发布状态](./releases)，核对来源、版本及是否仍使用旧 v0.4/v0.5 管理器；旧版升级需 [显式迁移管理器](./upgrade-migration#manager-migration)。v0.7 预览仍在开发、未发布、测试未定，不能靠改下载链接或给旧脚本加新参数获得托管能力。

版本/协议不兼容不是反复重试能解决的问题。不要把 `latest` 改成不存在的版本、下载任意分支安装器、改清单格式或跳过摘要检查；网络下载失败则按下一节排查。Pages 部署与程序 Release 仍是独立流程。

## 入口下载失败

- 检查命令中的完整项目路径 `/QQON-Panel/`，不是 GitHub Pages 域名根目录。
- Linux 管道的第一段需要 `curl` 或 `wget`；不存在下载工具时先准备工具或从可信电脑下载传入。
- 检查系统时间、CA、DNS、企业代理以及 GitHub HTTPS 可达性。不要加 `-k`、关闭证书检查或换不明镜像。
- 若 Pages 尚未启用或构建未成功，入口也可能 404；等待站点维护者完成部署，不自行创建“同名安装脚本”。
- 下载中断后应重新下载完整文件并核验，不继续执行残缺内容。

## 没有交互终端

网络管道的标准输入承载脚本，不承载菜单答案。交互入口需 `/dev/tty` 或 Windows 控制台；CI/非交互环境应先下载审阅，再使用该官方已发布安装器实际支持的明确参数。

`--yes` / `-Yes` 不代表关闭来源、权限、平台、数据格式或摘要校验，也不隐式批准更换管理器或错误公网地址；它与 `qqon update` 都不能授予 v0.7 的 root/LocalSystem 系统管理权限。不能混用 v0.4/v0.5/v0.6 和未发布 v0.7 的帮助与配置。

## Linux 平台或依赖被拒绝

核对 [支持矩阵](./support-matrix)。v0.6.0 提供 APT/DNF 安装路径，仍需要 root、活动 systemd、矩阵内发行版与受支持架构；无 systemd 的容器或矩阵外系统应停止，不能强行接管。

APT/DNF 失败先检查现有源、锁、网络与系统时间，不执行整机升级、替换源或关闭 SELinux 来满足面板安装。最小依赖安装失败不应迫使旧面板停服；保留完整错误但清除代理凭据后再报告。

## 已安装但打不开

安装有新维护入口时先用 `qqon status`、`qqon url` 查看只读状态与配置，不重复覆盖安装。旧 Linux 安装可使用：

```sh
sudo systemctl status server-panel.service --no-pager
sudo journalctl -u server-panel.service -n 80 --no-pager
```

- v0.6 新装默认公网 IPv4 自签 HTTPS `8443`；核对确认的 IPv4、实际端口、HTTPS 地址和可信终端证书指纹。
- 自签浏览器警告不等于网络故障。指纹或地址不一致时停止，不关闭全局证书校验；见 [公网 HTTPS](./public-https)。
- 公网 URL 仅为配置结果，**外网连通性未检测**。云安全组、主机防火墙和 NAT 需人工检查；本机成功不能证明外网可达。
- 旧 v0.4/v0.5 或仅本机模式继续回环／代理访问，默认 `127.0.0.1:5173`，不能直接用公网 IP 连接。迁移新管理器不自动开放公网。
- 端口被占用时确认占用进程，不随意终止陌生服务。按实际端口同步隧道、代理和网络规则。
- 检查 HTTPS Origin、Host 与访问地址一致，不关闭 Origin 验证；首次使用私有初始化令牌，没有默认密码，不删除账号文件重置账户。

## Windows 服务或权限错误 {#windows-errors}

本节适用于已发布的 **v0.6.0 Windows** 安装路径。新增 maintenance 隔离测试已在 CI 通过，但不意味着宿主真实 SCM/权限验收完成，详见 [Windows 服务](./windows-services)。

```powershell
Get-Service -Name QQONPanel
sc.exe qc QQONPanel
sc.exe queryex QQONPanel
```

- 找不到服务：确认安装器是否明确完成注册；尚未安装或安装未成功时，服务不存在是合理结果。
- 找不到 `qqon`：PATH 只有单独确认后才追加，需重开终端；未追加则使用安装结果给出的完整路径，不下载不明同名命令。
- 访问被拒绝：确认管理员 PowerShell 5.1 x64、NTFS、路径所有者及受保护 ACL。不要给 `Everyone` 授权或改成 SYSTEM/root 风格常驻来绕过问题。
- 重解析点或不明旧目录：停止接管，先备份并人工确认目录来源，不递归删除私有数据。
- 停止超时、文件被占用：确认服务/程序是否退出，保留事务；不要删锁、强行覆盖运行中程序或停用安全软件。
- 指标某项不可用：读取具体原因；首次速率采样、处理器组与系统卷限制不是生成假指标的理由。
- 网页系统服务列表或 Docker 不可用：这是 Windows 的范围边界，不照搬 Linux systemd/socket 命令。

## 摘要、清单或归档验证失败

不要执行未验证程序。检查是否从同一官方已发布 Release 获取完整附件、仓库/平台/版本是否正确，以及下载是否被代理替换为错误页面。保留非敏感错误信息；不要编辑 `release.json`、`SHA256SUMS` 或安装记录来“匹配”坏文件。

新旧协议差异按 [管理器迁移](./upgrade-migration#manager-migration) 处理，不关闭额外附件检查。

## 升级或恢复未结束

若提示存在未完成事务，按对应已知管理器的恢复流程处理。`qqon status`、`qqon url` 只读，不会恢复事务。不要反复更新、删除事务/旧程序备份或修改哈希；配置与 `qqon tls renew` 失败也须保留旧配置和证书记录，不忽略 TLS 校验继续。

恢复结束不代表自动重试了失败版本，应重新核对服务实际健康状态。账号与私有数据不会因二进制回退自动恢复到历史状态；需要数据恢复时先停止写入并制定独立方案，不能在没有备份时试错。

## v0.7 软件／网站／任务问题（预览开发中） {#hosting-preview}

当前 v0.4／v0.5／v0.6 没有真实软件安装或建站，v0.7 尚未发布、测试未定；旧版看不到新能力不是安装失败。以下仅供匹配本轮开发程序与管理器的隔离测试使用，详见 [托管开发指南](./hosting)。

- **管理权限不可用**：检查实际 root／LocalSystem 身份与受保护固定同意记录；普通 yes/update 不授权。按匹配的新 `qqon privilege` 流程独立同意，不手写记录、复制别处 JSON 或改服务身份绕过。
- **Windows 软件／网站不可用**：这是明确的平台边界；LocalSystem 不提供 Linux APT/DNF 或 Nginx 建站，不能靠继续提权解决。
- **软件任务失败**：检查任务 ID、阶段、现有可信 APT/DNF 源、锁、网络、包版本与服务状态；源模板不等于系统源。不要关签名、TLS、SELinux 或升级整机来强行继续。
- **安装成功但服务未运行／网站提示 Nginx 未运行或无可用 PHP runtime**：`install` 只安装并查询，不额外 `enable`／`start`。APT postinst 常启动服务，DNF 未必；先在软件页查看实际状态，显式 `start` Nginx，PHP 站点还需 `start` PHP-FPM，等待启动任务成功、刷新确认运行后再建站。安装成功不是已运行，`start` 成功也不是开机自启承诺，无需为启动而重复安装。
- **网站创建或更新失败**：检查 Nginx／PHP-FPM 实际依赖、revision、域名／面板主机隔离、端口与 `nginx -t`／reload 诊断。只操作受管配置，不覆盖主配置或未知站点。任务接受和本机标记成功都不等于外网可达。
- **文件被拒绝**：上传上限 2 MiB、文本编辑上限 256 KiB UTF-8；只接受受管根内安全普通文件。同名上传或 SHA-256 冲突应重读，不能强制覆盖；不解压归档。
- **TLS 导入失败**：核对 PEM、大小、有效期、域名 SAN、私钥匹配与站点端口；不要把私钥贴进日志。网站 TLS 不是 ACME，`qqon tls renew` 不续期网站证书。
- **任务中断或队列满**：先看已有任务，重启后 interrupted 不会自动重放；核对实际系统与事务恢复状态后再决定重试。失败可能已部分修改主机，不等于回到原状。
- **删除后磁盘仍有文件**：站点删除刻意保留 webroot，不提供本轮递归数据删除。软件 RAM 属于业务负载，不是面板自身指标异常。

## 报告问题

向 [项目 Issues](https://github.com/LinyuFiee/QQON-Panel/issues) 提供：系统与架构、实际 Release 版本/来源、安装或升级阶段、可复现步骤、脱敏错误和对应 CI 提交（若相关）。明确区分“编译通过”“临时目录模拟”“真实机器安装”。

不要上传账号 JSON、初始化令牌、TOTP/恢复码、Cookie、私钥、完整 ProgramData/数据目录或含代理密码的日志。注明实际 v0.6.0/v0.5.0/v0.4.0 预览版本；v0.7 开发代码须注明具体提交与未发布状态，不把开发行为当作已发布版本功能。
