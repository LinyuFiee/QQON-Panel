# 公网 IP HTTPS {#公网-ip-https-v0-6-开发中}

**[v0.6.0 预览版已发布](https://github.com/LinyuFiee/QQON-Panel/releases/tag/v0.6.0)**，新安装提供中文四模式向导。旧 v0.4/v0.5 保留原回环／代理访问，不自动切换公网。本页讲**面板访问 TLS**；未发布 v0.7 的网站 TLS 导入另见 [托管开发指南](./hosting#site-tls)，两者均不等于 ACME 自动签发。

## 新安装的默认流程

新安装默认采用 **`public-selfsigned`**：公网 IPv4、自签 HTTPS，默认端口 **`8443`**。中文交互中须由用户核对并确认服务器的公网 IPv4，再写入配置；不能把内网地址、代理出口或他人的 IP 当作自己的入站地址。

| 访问模式 | 适用方式 |
| --- | --- |
| 公网 IP 自签 HTTPS（默认） | 确认公网 IPv4，生成自签证书，默认 `8443` |
| 仅本机 | 回环访问，适合本机或自行配置 SSH 隧道 |
| 已有 HTTPS 代理 | 使用管理员已有的独立 HTTPS 入口，由代理提供 TLS |
| 导入证书 | 使用自行准备、与访问地址匹配的证书和私钥 |

默认访问地址形式为 `https://<已确认的公网IPv4>:8443/`，选择其他端口时以实际配置为准。该链接只表示配置结果，**未检测外网可达性**。旧版安装须按 [迁移顺序](./maintenance#从-v0-4-v0-5-迁移) 显式处理。

## 自签证书与浏览器提示

自签证书不受浏览器默认信任，访问时出现证书警告是预期现象，不代表已经获得公共 CA 认证。

- 从可信的服务器终端取得安装器或维护入口显示的证书指纹（SHA-256 fingerprint）。
- 在浏览器查看服务器证书，核对地址和指纹；只在确认来源与指纹一致后决定是否继续。
- 指纹不一致、地址不符或无法确认服务器身份时停止访问，不输入账号或初始化令牌。

不要为消除提示关闭浏览器或系统的全局证书检查。自签 HTTPS 提供加密，但不能替代身份核验和访问控制；证书私钥应保持私有。

## 还需要检查网络

安装器生成证书和访问配置，不等于以下条件自动满足：

| 条件 | 管理员需确认 |
| --- | --- |
| 公网 IPv4 | 地址确实属于本机或可转发到本机的入口，允许入站连接 |
| 云安全组 | 实际 HTTPS 端口的 TCP 入站规则及允许来源 |
| NAT / 路由 | 如有地址转换，公网端口正确转发到面板所在主机 |
| 主机防火墙 | 对应端口、接口和来源已按实际需要配置 |

`qqon status` 和 `qqon url` 只读查看本机状态及配置，不自动修复网络，也不证明外网可达。应从管理员控制的外部网络单独验证，不把本机访问成功当作外网验证通过；尽量限制允许访问的来源。

## 改配置与换证

- `qqon config` 用于显式调整访问配置；公网 IPv4 变化后须重新核对地址和对应证书。
- `qqon tls renew` 用于自签证书更新；换证后指纹可能变化，需要重新核对。
- 配置与证书切换使用事务，保留旧状态并检查结果；失败时保留记录，不跳过校验或删数据重装。

这些操作需 Linux root 或 Windows 管理员权限；当前 v0.6.0 服务仍使用受限账号，未发布 v0.7 的授权身份也不能由 `config`／`tls renew` 更改。它们不自动开通云安全组、NAT 或防火墙，不提供外网可达保证，也不等同自动申请受公共 CA 信任的证书。

旧版 v0.4/v0.5 必须先显式迁移管理器、保留旧访问，再升级新程序，最后选择是否配置公网 HTTPS。完整说明见 [qqon 维护](./maintenance)；当前已发布预览版安装见 [快速开始](./quickstart)。
